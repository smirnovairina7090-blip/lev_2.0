# Crystal Spider - подготовка модели к анимации и первая анимация ходьбы

## Что мы получили от Льва

Исходная модель `crystal_spider.bbmodel` проверена.

В ней:

- формат Blockbench: `Modded Entity`;
- текстура: 128 x 128;
- 16 геометрических элементов;
- отдельная голова;
- грудь и брюшко;
- 8 лап;
- 5 кристаллических шипов;
- анимационных клипов в самом bbmodel пока нет.

Форма модели нормальная. Геометрию переделывать не нужно.

Главная проблема была не во внешнем виде, а в структуре для анимации.

В исходнике лапы были объединены всего в две группы:

- `left legs`;
- `right legs`.

А в Java-экспорте Blockbench они превратились в имена вроде:

- `cube_r5`;
- `cube_r6`;
- `cube_r7`;
- ...

Так модель можно показать в игре, но объяснять и делать хорошую анимацию неудобно.

Для ходьбы нам важно уметь обратиться к каждой лапе отдельно:

```text
leg_front_left
leg_middle_front_left
leg_middle_back_left
leg_back_left

leg_front_right
leg_middle_front_right
leg_middle_back_right
leg_back_right
```

## Что именно исправлено

### 1. Геометрия не менялась

Размеры кубов, UV-развёртка и общий внешний вид сохранены.

### 2. Текстура correction-репозитория заменена

В репозитории преподавателя лежала более старая версия `crystal_spider.png`.

Текстура из bbmodel Льва совпадает с текстурой в его репозитории, поэтому именно её используем как актуальную.

### 3. Голова стала отдельной частью модели

Теперь в Java есть:

```java
private final ModelPart head;
```

и её можно поворачивать независимо от тела.

### 4. Каждая лапа стала отдельной ModelPart

Например:

```java
private final ModelPart legFrontLeft;
private final ModelPart legMiddleFrontLeft;
private final ModelPart legMiddleBackLeft;
private final ModelPart legBackLeft;
```

и четыре лапы справа.

Это самое важное изменение для анимации.

### 5. Точка вращения лапы перенесена ближе к телу

Если вращать длинный куб вокруг его середины, он выглядит как пропеллер.

Поэтому используется схема:

```text
leg_front_left       <- кость, точка вращения у тела
└── cube             <- сама геометрия лапы
```

Мы вращаем `leg_front_left`, а `cube` просто следует за ней.

Это обычная идея скелетной анимации:

```text
кость -> управляет
меш/куб -> рисуется
```

## Конструктор модели

После того как Minecraft "запёк" LayerDefinition, нужно получить ссылки на нужные ModelPart.

Например:

```java
this.legFrontLeft =
        this.root.getChild("leg_front_left");
```

Это буквально означает:

> найди внутри модели часть с именем leg_front_left и запомни её.

Если имя в `createBodyLayer()` и имя в `getChild()` не совпадут, игра упадёт при создании renderer.

## Что такое setupAnim

`setupAnim()` Minecraft вызывает постоянно перед отрисовкой сущности.

В него приходят данные о текущем состоянии движения.

Самые важные сейчас:

```text
limbSwing
limbSwingAmount
netHeadYaw
headPitch
```

### limbSwing

Положение внутри шага.

Можно представить круг:

```text
0 -> начало
PI -> половина
2PI -> полный цикл
```

Значение продолжает меняться, пока моб ходит.

### limbSwingAmount

Сила движения.

Если моб стоит:

```text
limbSwingAmount ≈ 0
```

поэтому амплитуда анимации тоже становится почти нулевой.

Если моб идёт:

```text
limbSwingAmount > 0
```

и лапы начинают заметно двигаться.

## Почему используется cos

В коде есть:

```java
Mth.cos(walkCycle)
```

cos даёт плавное число:

```text
1
↓
0
↓
-1
↓
0
↓
1
```

То есть лапа не телепортируется между двумя положениями, а плавно качается туда и обратно.

Упрощённо:

```text
+0.4 rad -> вперёд
0        -> середина
-0.4 rad -> назад
```

## Скорость и размах

```java
private static final float WALK_SPEED = 0.6662F;
private static final float WALK_AMOUNT = 0.45F;
```

`WALK_SPEED` отвечает за скорость цикла.

Больше число:

```text
лапы двигаются чаще
```

Меньше:

```text
паук переставляет лапы медленнее
```

`WALK_AMOUNT` отвечает за размах.

Больше:

```text
лапа сильнее уходит вперёд-назад
```

Меньше:

```text
движение становится спокойнее
```

## Почему часть лап получает + PI

Есть два варианта:

```java
Mth.cos(walkCycle)
```

и:

```java
Mth.cos(walkCycle + HALF_CYCLE)
```

где:

```java
HALF_CYCLE = PI
```

Сдвиг на PI переворачивает фазу.

Когда первая лапа идёт вперёд:

```text
cos(x)
```

вторая идёт назад:

```text
cos(x + PI)
```

Так все восемь лап не едут одновременно в одну сторону.

Получаются две чередующиеся группы.

## Почему вращаем yRot

У каждой ModelPart есть:

```text
xRot
yRot
zRot
```

Это вращение вокруг трёх осей.

Для первой версии ходьбы мы меняем:

```java
leg.yRot
```

То есть качаем лапу вперёд-назад вокруг вертикальной оси.

Это специально простая версия.

Позже можно добавить второе движение через `zRot`, чтобы лапы ещё немного поднимались и опускались.

## Поворот головы

Minecraft передаёт:

```text
netHeadYaw
headPitch
```

в градусах.

ModelPart работает с радианами.

Поэтому:

```java
private static final float DEG_TO_RAD =
        (float) Math.PI / 180.0F;
```

а затем:

```java
head.yRot = netHeadYaw * DEG_TO_RAD;
head.xRot = headPitch * DEG_TO_RAD;
```

Теперь голова может смотреть за целью, а тело при этом не вращается отдельно.

## Что НЕ нужно менять

Для этой анимации не нужно трогать:

- `CrystalSpider.java`;
- `ModEntities.java`;
- `CrystalSpiderRenderer.java`;
- `AzazelSAlchemyTableClient.java`.

Renderer уже умеет получать `CrystalSpiderModel`.

Entity уже наследуется от обычного `Spider`, поэтому Minecraft и так передаёт параметры ходьбы в `setupAnim()`.

## Как проверить

1. Собрать мод.
2. Запустить Minecraft.
3. Взять яйцо призыва Crystal Spider.
4. Поставить паука на ровную поверхность.
5. Отойти так, чтобы он начал преследовать игрока.
6. Смотреть именно на лапы.

Ожидаем:

- стоящий паук почти не двигает лапами;
- при ходьбе лапы качаются;
- соседние лапы работают в противоположных фазах;
- голова может менять направление;
- текстура и форма остаются такими же, как в модели Льва.

## Эксперименты ученику

### Эксперимент 1

Поменять:

```java
WALK_AMOUNT = 0.45F;
```

на:

```java
WALK_AMOUNT = 0.20F;
```

Вопрос:

> Что изменилось?

Ответ:

> уменьшился размах лап.

### Эксперимент 2

Поставить:

```java
WALK_SPEED = 1.2F;
```

Вопрос:

> Паук стал быстрее бегать?

Нет.

Изменилась только скорость анимации, а физическая скорость сущности осталась прежней.

Очень важное различие:

```text
скорость сущности != скорость анимации
```

### Эксперимент 3

Убрать `+ HALF_CYCLE` у одной лапы.

Посмотреть, как изменился ритм.

Так хорошо видно, зачем нужны фазы.

## Следующий логичный шаг

Когда эта анимация заработает, можно сделать второй слой движения:

- лёгкое поднятие лап через `zRot`;
- маленькое покачивание тела;
- отдельную позу атаки;
- реакцию кристаллов/шипов;
- idle-анимацию, когда паук стоит.

Но сначала лучше добиться чистой стабильной ходьбы только через `yRot`.
